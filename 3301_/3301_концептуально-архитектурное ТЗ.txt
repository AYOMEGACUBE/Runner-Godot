BLACKOUT — КОНЦЕПТУАЛЬНО-АРХИТЕКТУРНОЕ ТЗ (актуализация 3301)

Дата исходного документа: 2026-02-19.
Актуальное состояние кода и autoload: 3301_ROOT_README.md, 3301_PROJECT_STATE.md, индекс 3301_README.md; стена (JSON/текстуры): 3301_WALL_RENDERING_AND_STREAMING.md (сверка 2026-04-15).

Статус: Обязательная директива для runtime-архитектуры генерации и брендинга сторон.

============================================================
1. СТРАТЕГИЧЕСКОЕ НАПРАВЛЕНИЕ
============================================================
1) Стабильная математическая генерация без зацикливания.
2) Архитектурная готовность к коммерческому брендингу сторон мегакуба.

============================================================
2. PATHMODEL LIBRARY (ОБЯЗАТЕЛЬНО)
============================================================
- Используется библиотека из 50 PathModel.
- PathModel генерируются один раз, сохраняются, переиспользуются.
- Runtime не должен рассчитывать альтернативную аварийную вертикаль.

Дополнение к реализации (AS-IS): в коде есть опциональный стриминг колен из JSON-чанков
(DATA/PulseRunnerData/chunks/) при Level.use_path_leg_streaming и узле PathManager; основной
режим по умолчанию остаётся библиотека path_library_50.json. См. 3301_PROJECT_STATE.md.

Каждый PathModel:
- общий тренд около 2 градусов;
- 10 нерегулярных волн;
- локальные подъёмы и спуски;
- 1..3 обманки/конкурента в пределах волны.

============================================================
3. RUNTIME-ПРАВИЛА
============================================================
- На старте/смене выбирается PathModel + направление LEFT/RIGHT.
- Z-образная траектория обеспечивается сменой направлений.
- Запрещено использовать dual-vertical модель как основной механизм.
- Emergency vertical fix не является рабочим источником прогресса.
- Runtime работает в player-centered world window по X:
  - платформы поддерживаются в активном окне вокруг игрока;
  - спавн вне окна запрещён;
  - anchor X-clamp ограничивает горизонтальный дрейф генератора;
  - при переполнении пула выполняется batch pool recovery по удалённости от игрока.

============================================================
4. SIDEBRANDING (ОБЯЗАТЕЛЬНАЯ ЗАКЛАДКА)
============================================================
- Мегакуб: 6 сторон, side_id=1..6.
- Бренд задаётся на уровне стороны.
- Переключение бренда одной строкой:
  ACTIVE_SIDE_1_BRAND = X
  где X: 0=default, 1=CocaCola, 2=Pepsi, ...

Запрещено:
- хранить brand в каждой платформе;
- плодить уникальные платформы под бренд;
- менять core physics ради бренда.

============================================================
5. МОДЕЛЬ ДАННЫХ ПЛАТФОРМЫ
============================================================
Platform:
- geometry
- material_reference
- side_reference

Material выбирается через:
SideManager -> BrandID -> Material

============================================================
6. ГРАНИЦЫ 3.301
============================================================
Сейчас реализуем:
- архитектурный каркас PathModel/PathLibrary/PathSelector;
- архитектурный каркас SideManager/BrandConfig.

Не реализуем сейчас:
- IAP/серверную активацию брендов;
- серверную синхронизацию brand ownership.

============================================================
7. КРИТЕРИЙ ГОТОВНОСТИ
============================================================
- Normal-path генерация является основной.
- Нет циклической деградации в emergency-only.
- 50 моделей загружаются из библиотеки, не пересчитываются каждый запуск.
- Бренд стороны меняется одной константой, без влияния на path-генерацию.
