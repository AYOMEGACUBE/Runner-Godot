ТЕХНИЧЕСКОЕ ЗАДАНИЕ ДЛЯ ИИ: КАРТА РАССТАНОВКИ ПЛАТФОРМ (НЕЙТРАЛЬНОЕ)
Назначение: скопировать целиком в контекст любой языковой модели. Выход встраивается
в общий JSON-библиотеку путей игры (см. раздел «ИНТЕГРАЦИЯ В БИБЛИОТЕКУ»).
Движок: Godot 4, 2D runner. Подробности bake и правил — в документации репозитория
(файлы с префиксом 3301_, раздел PathModel / path library).
================================================================================

РОЛЬ МОДЕЛИ
-----------
Ты — генератор геометрии уровня. На вход получаешь числовые параметры забега. На выход
отдаёшь ТОЛЬКО один валидный JSON-объект (без markdown-обёрток, без пояснений до/после),
строго по схеме раздела «ФОРМАТ ВЫВОДА». Все числа — десятичные, координаты в px.

СИСТЕМА КООРДИНАТ (ОБЯЗАТЕЛЬНО)
--------------------------------
- Плоскость Godot 2D: ось X вправо, ось Y ВНИЗ (больше Y = ниже на экране).
- «Подъём» пути = следующая опорная платформа имеет МЕНЬШЕ Y, чем предыдущая (в среднем).
- Центр платформы: (x, y). Ширина w ∈ {64, 128, 256}, высота h = 64.
- Левый край: x - w/2, правый: x + w/2, верх AABB: y - 32, низ: y + 32.

КОНСТАНТЫ МИРА И ЭКРАНА
-----------------------
- Ширина мира: 153600 px. Обычно min_x = 0, max_x = 153600 (центры платформ так, чтобы
  AABB не выходила за границы).
- Высота мира: 153600 px (диапазон по Y задаётся min_y, max_y; все платформы внутри).
- Эталон логического экрана (UI): BASE_WIDTH = 1080, BASE_HEIGHT = 1920 (не размер мира).

ФИЗИКА ПРЫЖКА (ДЛЯ ПРОВЕРОК)
----------------------------
Используй фиксированные значения (как в игре):
  GRAVITY = 2000
  JUMP_VELOCITY = -960
  MOVE_SPEED = 350
  jump_reach_max_fraction = 0.8
  safe_margin_x = 32
  min_edge_gap = 32
  vertical_gap = 0
  platform_half_height = 32

Эталонные максимумы (ровная поверхность, ΔY поверхностей = 0):
  R_ref ≈ 336 px — ориентир горизонтальной досягаемости по краям платформ.
  H_max ≈ 230 px — макс. высота прыжка.

Поверхность платформы i: surf_i = y_i - platform_half_height

Для соседних опорных платформ i → i+1 по ПОРЯДКУ ПУТИ:
  delta_surf = surf_{i+1} - surf_i
  disc = JUMP_VELOCITY*JUMP_VELOCITY + 2*GRAVITY*delta_surf
  Если disc < 0 — прыжок невозможен, такую пару запрещено.
  t = (-JUMP_VELOCITY + sqrt(disc)) / GRAVITY
  reach = MOVE_SPEED * t * jump_reach_max_fraction

Половины ширин по сегментам (тайл 64 px): segments ∈ {1,2,4} → ширина {64,128,256}.
  half_i = segments_i * 32
edge_dx = abs(x_{i+1} - x_i) - half_i - half_{i+1}
Условие проходимости: edge_dx <= reach - safe_margin_x  (с небольшим запасом ≥ 0)

ТИПЫ ПЛАТФОРМ
-------------
- "normal" — опорная, vanish=0, is_decoy=false
- "crumble" — опорная, осыпается; vanish=1, is_decoy=false
- "decoy" — только визуал, БЕЗ коллизии с героем; vanish=0, is_decoy=true
  Decoy НЕ входит в support_chain_indices; не размещай decoy «в линию» между двумя
  опорными так, будто это следующий шаг маршрута — см. раздел «НЕ ОДНА ЛИНИЯ».

СТРУКТУРА УРОВНЯ: НЕ ОДНА ЛИНИЯ (ОБЯЗАТЕЛЬНО, УСИЛЕННОЕ ТРЕБОВАНИЕ)
--------------------------------------------------------------------
Уровень — это НЕ одна вереница платформ по одной траектории.

A) Опорный маршрут (support_chain_indices) — единственная цепочка, по которой герой
   реально может пройти; между соседними опорными — все правила gap / reach / прыжок.

B) Ложные / приманки (decoy, is_decoy=true):
   - Должны создавать **иллюзию разветвления**: часть платформ «рядом», но до них
     **нельзя допрыгнуть** ни с одной опорной платформы маршрута (ни с предыдущей,
     ни с ближайшей по X в разумном окне). Формально: для каждой decoy D и каждой
     опорной S вычисли reach(S→D) по формулам раздела «ФИЗИКА» (как если бы D была
     следующей целью); должно быть edge_dx > reach - safe_margin_x + 40 (запас
     «недостижимо») ИЛИ |Δy поверхностей| > H_max * 1.15 (вертикаль не взять прыжком
     с этой опорной). Минимум одно из условий «далеко» обязано выполняться для пары (S,D).
   - **Сверху и снизу относительно полосы маршрута:** построй ломаную по центрам опорных
     (порядок support_chain). Для каждой decoy укажи в JSON поле "bait_band": "above" |
     "below" | "side" (рекомендуется только above/below для «ложных наверху/внизу»):
     "above" — центр decoy минимум на 120 px **выше** по экрану (меньше Y), чем линейная
     интерполяция y_mroute(x) по двум ближайшим опорным по X; "below" — минимум на 120 px
     **ниже** (больше Y), чем y_mroute(x). Не менее **40%** всех decoy — "above", не менее
     **40%** — "below" (остаток может быть "side": смещение по X за пределы досягаемости).
   - Decoy **запрещено** ставить строго между двумя соседними опорными на одной высоте
     так, что визуально продолжает коридор — пользователь должен видеть «обманные»
     полки **вне** достижимой дуги, преимущественно выше и ниже основной линии.

C) Подъём и спуск героя по **опорной** цепи (не монотонный забег только вверх):
   - Среди последовательных пар опорных (по support_chain_indices) должны встречаться
     **оба** направления по Y:
     • «шаг вверх по экрану»: y_{k+1} < y_k (центр следующей выше),
     • «шаг вниз по экрану»: y_{k+1} > y_k.
   - Если число опорных N >= 12: минимум **ceil(N * 0.12)** пар со спуском (вниз) и
     минимум **ceil(N * 0.12)** пар с подъёмом (вверх) — чередование, без длинных
     монотонных отрезков > 6 опорных подряд только в одну сторону по Y.
   - Итог от A до B: суммарный подъём (y_A - y_B) остаётся в духе угла ~5° в среднем,
     но **локально** траектория «волнистая» (зигзаг по высоте в пределах |Δy| <= 900
     между соседними опорными).

ОГРАНИЧЕНИЯ (СГЕНЕРИРОВАННАЯ КАРТА ДОЛЖНА ИМ ВОЗМОЖНО БОЛЕЕ СООТВЕТСТВОВАТЬ)
----------------------------------------------------------------------------
1) Угол подъёма: для опорных платформ от первой (A) до последней (B) в списке пути
   средняя линия должна давать угол ≈ 5° к горизонтали «в сторону подъёма по экрану».
   Пусть Δx = x_B - x_A, подъём по экрану (положительный вверх) = (y_A - y_B).
   Тогда tan(целевой_угол) ≈ tan(5°) ≈ 0,0875 ≈ (y_A - y_B) / Δx при Δx > 0.
   Если бег в сторону уменьшения X — согласуй направление и знак Δx в отчёте meta.

2) Вертикаль между соседними ОПОРНЫМИ: |y_{i+1} - y_i| <= 900 px (от центра к центру
   или от поверхности к поверхности — выбери одно и применяй единообразно; предпочтительно
   от центра к центру для простоты).

3) Горизонтальный зазор между ближайшими краями соседних ОПОРНЫХ i и i+1 вдоль пути:
   пусть gap_x = расстояние между правым краем одной и левым краем следующей, если движение
   вправо (иначе симметрично). Тогда:
   gap_x ∈ [ 0.40 * R_ref , 0.90 * R_ref ] ≈ [ 134.4 , 302.4 ] px.
   Округление до целых: [134, 302] допустимо.

4) Не пересечение AABB: для любой пары платформ (включая decoy) прямоугольники
   с половинами w/2 и 64/2 НЕ пересекаются, если отступить min_edge_gap по X и
   vertical_gap по Y между их AABB (как в игре: минимум 32 px между краями по X при
   близкой высоте; при |y_i-y_j| > 64 + vertical_gap допускай больше свободы, но без пересечения).

5) Цепочка прыжков: для каждой пары соседних ОПОРНЫХ по порядку пути выполни формулу
   reach и edge_dx выше; должно выполняться edge_dx <= reach - safe_margin_x.

6) Видимость «не более 8»: эвристика для генерации — вдоль пути не размещай плотные пачки
   опорных платформ так, чтобы в прямоугольнике 1080×1920 с центром на текущей опорной
   одновременно попадало > 8 опорных AABB. Если полная проверка сложна, минимизируй
   вертикальное сгущение: чередуй gap_x в допустимом диапазоне и |Δy| <= 900.

7) Хаотичность: внутри допустимых диапазонов варьируй gap_x, Δy, size (small/medium/large),
   тип (normal/crumble/decoy) по seed; без идентичных повторов подряд > 3 раз.

8) Доля приманок: среди **всех** слотов platforms минимум **25%** — decoy (is_decoy=true),
   при N_total >= 20; иначе минимум 5 decoy. Соблюдай распределение bait_band above/below
   из раздела «НЕ ОДНА ЛИНИЯ».

ВХОДНЫЕ ПАРАМЕТРЫ (ПОЛЬЗОВАТЕЛЬ ПОДСТАВЛЯЕТ В ПРОМПТ)
----------------------------------------------------
Перед генерацией пользователь задаёт (ты читаешь из его сообщения):
- seed: int
- start: { "x": float, "y": float } — центр первой опорной платформы (точка A)
- direction_x: +1 или -1 — направление бега
- platform_count: int — число опорных платформ в цепочке (рекомендуется 24–80)
- optional: decoy_ratio float 0.25..0.45 — целевая доля decoy среди всех слотов (дефолт 0.3)
- optional: crumble_ratio float 0..0.5 — доля crumble среди опорных
- world_y_min, world_y_max, world_x_min, world_x_max — если не заданы, использовать
  x ∈ [0,153600], y так чтобы вписаться в высоту 153600 относительно старта (см. meta).

ФОРМАТ ВЫВОДА (СТРОГО)
----------------------
Верни один JSON:

{
  "schema_version": 1,
  "meta": {
    "seed": <int>,
    "direction_x": <1|-1>,
    "world": { "x_min": 0, "x_max": 153600, "y_min": <float>, "y_max": <float> },
    "angle_target_deg": 5,
    "angle_achieved_deg": <float>,
    "R_ref_px": 336,
    "gap_x_range_px": [134, 302],
    "support_ascent_segments_count": <int>,
    "support_descent_segments_count": <int>,
    "decoy_count": <int>,
    "decoy_bait_above": <int>,
    "decoy_bait_below": <int>
  },
  "platforms": [
    {
      "order": 0,
      "x": <float>,
      "y": <float>,
      "segments": <1|2|4>,
      "size": "small"|"medium"|"large",
      "kind": "normal"|"crumble"|"decoy",
      "vanish": 0|1,
      "is_decoy": true|false,
      "bait_band": "above"|"below"|"side"|"route"
    }
  ],
  "support_chain_indices": [ <int>, ... ]
}

Пояснения:
- platforms — ВСЕ слоты (опорные + decoy), порядок в массиве = порядок обхода генерации.
- support_chain_indices — индексы в platforms опорных платформ в порядке пути героя
  (is_decoy=false), по ним проверяются угол A→B, gap_x, прыжки, ±900.
- vanish=1 только для crumble; decoy: vanish=0, is_decoy=true.
- segments: small=1, medium=2, large=4.
- bait_band: для опорных всегда "route"; для decoy — "above" | "below" | "side" (см. ТЗ).
- meta.support_ascent_segments_count / support_descent_segments_count — число пар подряд
  в support_chain с y_{k+1}<y_k и с y_{k+1}>y_k соответственно.
- meta.decoy_bait_above / decoy_bait_below — сколько decoy с bait_band "above" и "below".

ИНТЕГРАЦИЯ В БИБЛИОТЕКУ (ДЛЯ ЧЕЛОВЕКА / АГЕНТА, НЕ ДЛЯ ВЫВОДА МОДЕЛИ)
----------------------------------------------------------------------
Не создавай отдельный файл карты уровня. Ответ модели встраивается как ОДИН элемент массива
в JSON библиотеки путей:

  res://DATA/PulseRunnerData/path_library_50.json

Формат элемента библиотеки (минимум для предзаданной геометрии):

{
  "model_id": <уникальный int, не пересекающийся с другими элементами массива>,
  "trend_degrees": 5,
  "steps": [],
  "platforms": [ ... скопировать массив platforms из ответа модели ... ],
  "support_chain_indices": [ ... скопировать из ответа модели ... ]
}

Поля schema_version и meta из ответа модели в библиотеку класть не обязательно — рантайм
их не читает; их можно оставить только в черновике для отладки. Поля order, kind, size,
bait_band в объектах platforms допустимы в JSON: движок при загрузке использует x, y,
segments, vanish, is_decoy; остальное игнорируется.

Если у модели пустой platforms[] и непустой steps[] — уровень выпекает путь из шагов (как
обычные записи библиотеки). Если platforms[] непустой — уровень выравнивает первую опорную
платформу к фактическому старту и прогоняет validate_full по support_chain_indices.

САМОПРОВЕРКА ПЕРЕД ОТВЕТОМ
--------------------------
1) JSON парсится без ошибок.
2) Все платформы внутри world из meta; meta.world по высоте осмысленна для всего уровня
   (рекомендуется span по Y не меньше 153600 или явный диапазон, покрывающий все y слотов).
3) support_chain_indices непустой, монотонно по X в сторону direction_x (строго возрастающий
   x при direction_x=1).
4) Для каждой пары подряд в support_chain_indices: gap_x по краям в [134,302] (±2 px) И
   edge_dx <= reach - safe_margin_x (прыжок возможен). Пересчитай X опорных после вставки
   decoy так, чтобы п.4 выполнялся для **всех** пар опорных, а не только соседних в массиве
   platforms.
5) |Δy| между соседними опорными <= 900.
6) Нет пересечения AABB (с учётом min_edge_gap 32 px для близких по Y).
7) Угол ~5° по опорным A→B: achieved в meta, отклонение до ±1.5°.
8) Опорная цепь: есть и подъёмы, и спуски по Y (см. п.C); meta-поля ascent/descent ≥ порогов.
9) Каждая decoy: недостижима с каждой опорной по критерию раздела «НЕ ОДНА ЛИНИЯ» п.B;
   bait_band заполнен; доли above/below соблюдены; не менее 25% слотов — decoy при N≥20.
10) Нет decoy «в коридоре» между двумя соседними опорными на одной высоте с ними
    (запрет из п.B).

ЗАПРЕТЫ
-------
- Не выводить текст вне JSON.
- Не использовать NaN/Infinity.
- Не ставить опорные платформы с невыполнимым прыжком от предыдущей опорной.
- Не генерировать уровень из одной линии платформ без недостижимых decoy сверху/снизу
  и без спусков/подъёмов по опорной цепи.
